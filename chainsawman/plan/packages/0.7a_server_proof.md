## What the player gets

On a server with friends or strangers, Pochita can't be stolen or lost for good, going down can't be dodged by
logging out, a totem works, and one player can't lock the heart away by accident. Alone, nothing changes.

- You merge by dying with Pochita carried or tamed near you. That stays. [kortev]

## Facts (code under `chainsawman/src/main/java/io/github/kortev/chainsawman/`; read before you change)

- `PochitaItem.carried(player)` is true for any Pochita item in the inventory, whoever tamed him.
- `form/Merge.comes(player)` = not merged, `Owner.is(player)`, and (carried, or a tamed Pochita of theirs near).
  It doesn't count how many hearts are already taken.
- A dropped Pochita item despawns like any item, and nothing calls `PochitaPlace.lost`.
- `Owner` keeps a player **name** (set by `/chainsaw owner <player>`); nobody by default, so anyone passes.
- `form/Fallen.java` (about lines 98-103 and 238): going down is decided in `ALLOW_DEATH`, and bleeding out uses
  `genericKill`. From memory, not tested: `ALLOW_DEATH` fires before Minecraft's totem check, so a totem never pops.
- Logging out while down: the body goes and the timer stops (`form/Downed`, `form/Fallen`).
- `form/Legend.java`: the `legendRoar` game rule is on by default.

## Build

1. **Pochita belongs to his tamer.** The item remembers its tamer's player id (a data component). Only the tamer's
   own Pochita counts in `carried`. An old item with no tamer takes the first player who holds it. In anyone else's
   inventory he jumps out within a second as his tamed self, still the tamer's.
2. **A lost Pochita goes back to a den.** His dropped item never despawns from age. If it's destroyed (lava, fire,
   cactus, the void, a blast), call `PochitaPlace.lost` so a den gets him again.
3. **Hearts are counted at the merge.** If `chainsawHearts` players are already merged, `Merge.comes` is false and
   the death goes on as normal. When the last heart is taken, every other tamed, un-merged Pochita turns wild
   (loaded ones now; others when their chunk loads or their holder next ticks).
4. **Logging out while down doesn't save you.** Save the bleed-out time against the world clock. Log back in before
   it: still down, same time left. After it: you die on arrival, where you fell. In a single-player world the clock
   stops with the game, so nothing changes there.
5. **A totem pops first.** First write a test that shows what happens today. If a held totem doesn't pop, let
   Minecraft use it before going down. Bleeding out uses the damage source that put you down, so the death message
   and the kill credit are right.
6. **The owner is kept by player id.** `/chainsaw owner <player>` stores the id and shows the name. A saved name
   from before turns into an id the next time that player joins.
7. **`legendRoar` is off by default.**
